# Проверка целостности спек

Коды требований (`ЗАК-Ф-12`, `АДП-О-11`) — это ссылки: их цитируют в issue, в
комментариях к коду, в других спеках. Ссылка работает, только пока код
уникален и стабилен. Сломать это легко и незаметно — достаточно вставить
требование в середину списка и сдвинуть нумерацию.

## Запуск

```bash
node .claude/skills/spec-lint/check-specs.js
```

Из корня умбрелла-репозитория. Код возврата: `0` — чисто, `1` — есть нарушения.
Флаг `--json` даёт машинночитаемый вывод.

## Что проверяется

| Проверка | Что ловит |
|---|---|
| Дубли | Один код у двух требований — цитата становится неоднозначной |
| Висячие ссылки | Упоминание кода, который нигде не определён (опечатка либо удалённое требование) |
| Пропуски номеров | Номер отсутствует, хотя большие есть: требование удалено без пометки |
| Реестр блоков | Блок используется в спеке, но не заведён в `.specify/memory/blocks-registry.md` |
| Оглавление | Пункт оглавления ведёт к заголовку, которого в файле нет |

## Правило, из которого всё следует

**Занятый код не переиспользуется под другой смысл — даже после удаления
требования.** Удалили требование — его номер остаётся выведенным из
употребления навсегда, а новое получает следующий свободный.

Объявляется это строкой в самой спеке, сразу после списка требований блока:

```markdown
*`РАБ-Ф-05` и `РАБ-Ф-06` не используются: они принадлежали предпросмотру,
который убран. Коды не переиспользуются под другой смысл — см. реестр.*
```

Проверка распознаёт такую строку и исключает эти коды из «висячих ссылок» и
«пропусков номеров». Без неё удалённый номер будет отмечен как пропуск.

## Чего проверка сознательно НЕ делает

**Не требует, чтобы номера шли по возрастанию.** Требования сгруппированы по
тематическим подразделам («Изображения», «Списки и таблицы»), и новое кладётся
в свой подраздел, а не в конец блока — поэтому номера законно идут вразбивку.
Тематическая группировка полезнее числового порядка; номер нужен лишь как
уникальная стабильная ссылка.

## Если проверка нашла нарушение

Дубль или пропуск чаще всего означает, что при вставке требования сдвинули
чужие номера. Правильное исправление — **вернуть исходные номера на место**, а
новое требование добавить со следующим свободным, даже если по смыслу ему место
в середине списка. Порядок в файле и номер — независимые вещи.
