# Сверка PROJECT_MAP.md с веткой

`CLAUDE.md` обоих сабмодулей требует: заканчивая задачу, агент **сам, без
напоминания** дописывает в `PROJECT_MAP.md` всё новое, что создал. Правило
легко забыть — оно срабатывает в самом конце работы, когда задача уже
ощущается сделанной. Этот скилл превращает «не забыть» в проверку.

## Когда запускать

- перед сменой статуса задачи на «выполнена»;
- перед открытием PR (открытие PR = переход в «выполнена», см. `CLAUDE.md` умбреллы);
- после любой задачи, создавшей что-то новое.

## Как проверять

Работать нужно **внутри сабмодуля** (`backend/` или `frontend/`) — у каждого
свой `PROJECT_MAP.md` и своя история.

**1. Что появилось в ветке относительно master:**

```bash
git diff master...HEAD --diff-filter=A --name-only
```

`--diff-filter=A` оставляет только добавленные файлы — именно они чаще всего
и есть «новое, что нужно занести в карту». Изменённые файлы смотреть тоже
стоит, если в них добавился публичный метод или опция:

```bash
git diff master...HEAD --name-only
```

**2. Что из этого попадает в карту.** Ориентир — то, что уже перечислено в
`PROJECT_MAP.md`, а не общие соображения. Обычно это:

| Репозиторий | Что заносится |
|---|---|
| `streamer.API` | Модули, контроллеры и эндпоинты, сервисы с их публичными методами, guard'ы и interceptor'ы, модели Prisma, опции окружения |
| `stream.Front` | Компоненты, сервисы с методами, guard'ы и interceptor'ы, роуты, design tokens, опции окружения |

**3. Сверить с текущим содержимым карты** и дописать недостающее. Указывать
там же номер issue и PR — карта служит и указателем «где это появилось».

## На что смотреть внимательно

- **Публичный метод, добавленный в существующий сервис** — файл в диффе
  числится изменённым, а не добавленным, и потому теряется легче всего.
- **Новая опция окружения** — она попадает в `.env.example`, но в карту её
  забывают; при этом именно карта отвечает на вопрос «что нужно настроить».
- **Удалённое** — карта описывает то, что есть сейчас. Убранный компонент
  надо не только не забыть, но и вычеркнуть.

## Что это не проверяет

Скилл не сверяет карту с кодом целиком — только с изменениями текущей ветки.
Полная ревизия карты (не устарела ли она в местах, которых задача не касалась)
— отдельная работа, которая делается осознанно, а не походя в конце задачи.
