# Доска: как менять статусы

Справочник для агентов, ведущих задачи автономно. Без него смена статуса
превращается в раскопки идентификаторов при каждом обращении.

Доска — [steramer.io — Разработка](https://github.com/users/MACTEPwar/projects/3),
номер `3`, владелец `MACTEPwar`. К ней подключены все три репозитория.

## Найти карточку задачи

`item-list` возвращает карточки вместе со статусом. **Лимит по умолчанию — 30**,
и он молча обрезает выдачу: на доске больше сотни карточек, поэтому лимит
задавать явно, иначе задача покажется отсутствующей.

```bash
gh project item-list 3 --owner MACTEPwar --limit 300 --format json
```

Нужен `id` карточки (`PVTI_…`) той записи, где `content.number` — номер issue,
а `content.repository` заканчивается нужным репозиторием: номера в разных
репозиториях совпадают, и по одному номеру карточка находится неоднозначно.

## Поставить статус

```bash
gh project item-edit --id <PVTI_…> \
  --project-id PVT_kwHOAgEyrM4BdEhL \
  --field-id PVTSSF_lAHOAgEyrM4BdEhLzhXowVs \
  --single-select-option-id <ID варианта>
```

## Добавить задачу на доску

Новая issue на доске не появляется сама:

```bash
gh project item-add 3 --owner MACTEPwar --url <ссылка на issue>
```

Добавленная карточка приходит **без статуса** — его нужно проставить отдельно,
иначе задача не попадёт ни в одну колонку.

## Когда какой статус

| Момент | Статус | Кто ставит |
|---|---|---|
| Задача заведена, ждёт очереди или зависимости | Бэклог | тот, кто заводит |
| Готова к работе, зависимости сняты | К выполнению | тот, кто заводит или освобождает зависимость |
| Взята в работу | В работе | исполнитель, сразу как взял |
| Открыт PR | Выполнена | исполнитель, вместе с открытием PR |
| Найдена проблема при проверке | Возвращена в работу | проверяющий, с лейблом роли, которая чинит |
| Принято | Проверена | **только человек**, вместе с мержем и закрытием issue |

Смена статуса сопровождается комментарием в issue: что сделано и что требуется
дальше. Статус говорит «где задача», комментарий — «что с ней произошло»;
одного без другого недостаточно.

## Лейбл роли

Лейбл (`ba`/`frontend`/`backend`/`devops`/`qa`) показывает, кто действует
сейчас. При хендоффе исполнитель ставит лейбл следующей роли **и** статус
«К выполнению» — иначе следующая роль задачу не увидит.

```bash
gh issue edit <N> --repo <owner/repo> --remove-label frontend --add-label qa
```
